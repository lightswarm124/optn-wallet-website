# Content Suggestions

Use this as a checklist for tightening the site with real material.

## Homepage

Hero:
- One-line company description
- One-line subheading that says what you build and for whom
- Primary CTA: one action only

Add:
- A short logo strip if you have partners, customers, or grants
- A small "Used by" or "Working with" block if logos are available
- A short metrics row only if the numbers are real and current

Good homepage proof content:
- Number of active integrations or partner teams
- Networks supported: mainnet, chipnet
- Current products: wallet, hosted services, engineering support
- Public repo activity if it is active and worth showing

## Wallet Page

Best content to add:
- 3 to 5 actual wallet features
- A short release notes block
- Screenshots with short captions
- Link to the repo and store listing

Useful concrete copy:
- "Supports CashTokens"
- "Built for more advanced BCH transaction flows"
- "Available on Android"

## Hosted BCH Services Page

Best content to add:
- Which services are currently available
- Who the service is for
- Expected onboarding process
- What information a team should send before access is granted

Useful concrete copy:
- "Hosted indexing and history access"
- "Electrum connectivity"
- "BCMR and metadata support"
- "Access is scoped to workload and product needs"

## Engineering Support Page

Best content to add:
- Typical project types
- What support can look like: review, implementation help, launch support
- Example questions teams come with
- Short case studies once available

Useful concrete copy:
- "Architecture review for BCH products"
- "Help with CashTokens and covenant-related flows"
- "Implementation support for wallet and backend work"

## Blog / Updates

Best next posts:
- Product update: what changed in OPTN Wallet
- Infrastructure update: what hosted services are available now
- A practical BCH engineering post tied to real product work
- A short note on how teams can work with OPTN Labs

## Tone Rules

Prefer:
- Direct nouns and verbs
- Short sentences
- Specific product language
- Plain description over persuasion

Avoid:
- "proof"
- "why this matters"
- "best fit"
- "built for serious teams"
- language that sounds like it is trying to justify credibility instead of showing it
